termd 0.9.1

用户可见变化:
- 改进 daemon 到 relay 的 control 长连接保活：空闲 Ping 只有收到 payload 匹配的 Pong 才算成功，避免本地 socket 写入成功却实际路由已断的“半开连接”长时间留在 relay 中。
- relay control 链路无响应时，daemon 现在会在约 10–20 秒内识别并重连，减少 relay 仍显示 daemon 在线、但新的终端或 HTTP 请求报 `relay could not forward the application request` 的情况。
- 心跳超时优先于其他连续入站消息处理，错误 payload 的 Pong 也不会误确认当前 Ping；对应的无 Pong、匹配 Pong 和错误 Pong 回归测试已补齐。

兼容性:
- control 和 data pipe 协议未变；建议 `termd` 与 `termrelay` 同步升级到 `0.9.1` 以保持版本一致，旧客户端无需重新配对。
- supervisor 兼容版本保持 `2026-07-12-dual-ws`；普通升级只重启 daemon 进程，不会终止或清空现有终端 session/supervisor。
- 本修复针对长时间失效的 relay control 路由；短暂的公网、TLS 或反向代理抖动仍可能导致单次请求重试，但不再需要等待长时间的 TCP 超时才清理失效 control 连接。
