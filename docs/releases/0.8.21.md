termd 0.8.21

用户可见变化:
- 新增 `termd offer-file <PATH>`：AI Agent 或其他本地进程可以把已完成的单个文件推送给当前连接的已配对客户端，不需要先找到对应 session 或手工进入文件列表。
- Web 端以不占用页面布局高度的悬浮提示展示文件路径和大小；原生下载完成或失败后仍可重试，由用户显式关闭提示。
- direct daemon 和 trusted relay 均支持原生流式下载，不在 JavaScript 内存中缓冲整个文件；移动 Chrome 和 iPhone WebKit 路径纳入真实浏览器回归。
- 内置 `termd-file-offer` Agent skill，可通过 `termd skill install --agent auto` 显式安装，让支持 skill 的 AI Agent 知道在生成文件后调用 `termd offer-file`。
- 应用内通知始终开启；系统通知在浏览器授权后自动订阅，不再提供应用级开关。

安全与兼容性:
- daemon 默认在 `0600` 的 `/run/termd/termd.sock` 上接受版本化 HTTP-over-Unix-socket 命令；能访问该 socket 即代表有权让 daemon 读取并推送文件。
- 只接受解析后为普通文件的路径。创建 offer 时记录 SHA-256，下载前生成私有快照并校验原文件；文件被删除、替换或修改后，旧 offer 不会静默下载新内容。
- File Offer 是 daemon-global 的短暂事件，不归属任何 session，不保存到 relay 中，也不在重连后自动重放；需要再次提示时重新调用 `termd offer-file`。
- 新增 `file.offer` 和三条精确的 relay HTTP allowlist 路径；为使用 relay 下载，`termrelay` 和 `termd` 应同步升级到 `0.8.21`。旧客户端会忽略未知的推送事件。
- workspace、Cargo lockfile 和 Web 前端版本同步到 `0.8.21`。supervisor 兼容版本保持 `2026-07-12-dual-ws`；从 `0.8.20` 普通升级不会清空 session 或终止现有 supervisor。
- GitHub Release 继续只发布 `termd`、`termctl`、`termrelay` 的 Linux amd64/arm64 六个裸二进制。
