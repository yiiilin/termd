termd 0.9.0

用户可见变化:
- 新增 Browser Workspace：已配对的 Web 客户端可以输入 HTTP(S) 地址，在独立窗口中通过 noVNC 操作 daemon 主机上的 Chromium；Browser Session 独立于终端会话，客户端断开或普通 daemon 重启不会自动关闭。
- Browser 下载完成后会自动进入现有 File Offer 流程，当前连接的客户端可直接接收提示并下载，不需要再到文件列表中查找。
- 新增 `termd browser` 本地自动化命令，支持列出、打开、导航、页面快照、点击、填写、等待下载和关闭 Browser Session；内置 `termd-browser` Agent skill 可通过 `termd skill install --agent auto` 安装，让 AI Agent 操作用户看到的同一个 Chromium。
- Web 端新增 Browser 管理对话框、运行中会话列表、独立 Viewer、重连、全屏和显式停止操作；direct daemon 与 trusted relay 均支持 Browser 控制和 RFB 数据转发。
- GitHub Release 新增 Linux amd64/arm64 Browser Runtime 资产。termd 会按自身版本和架构下载并校验包含 TigerVNC、Openbox 及必要运行库的 runtime，宿主只需另外安装 Chromium。

安全与兼容性:
- Browser 只接受绝对 HTTP(S) URL，视口限制为 `640..3840 x 480..2160`，每个 daemon 最多同时运行四个 Browser Session；停止会话会关闭页面并清理对应私有 profile。
- RFB、X11 和自动化控制均使用私有 Unix socket，不开放 VNC、X11 或 Chrome DevTools TCP 端口。浏览器访问继续使用现有设备配对和 access token；relay 只做认证后的 opaque routing，不保存 Browser Session 或 profile 状态。
- root daemon 会把 Chromium 降权到非 root 身份并保留 Chromium sandbox；runtime 归档会校验版本、架构、大小、SHA-256、路径和文件类型，拒绝 symlink、hardlink、绝对路径与路径穿越。
- Browser Runtime 首期支持 glibc `2.31+` 的 Linux amd64/arm64；Chromium 不包含在 release 中，未安装 Chromium 或 runtime 不可用时 Browser 创建会失败，但不影响终端、文件推送或其他 relay 路由。
- Browser 路由和自动化接口要求 `termd` 与 `termrelay` 同步升级到 `0.9.0`。旧客户端会忽略未知 Browser 事件，原有终端和 File Offer 行为保持兼容。
- workspace、Cargo lockfile 和 Web 前端版本同步到 `0.9.0`。supervisor 兼容版本保持 `2026-07-12-dual-ws`；从 `0.8.21` 普通升级不会清空现有终端 session，也不会终止既有 session supervisor。
- GitHub Release 现在发布六个 Linux amd64/arm64 裸二进制，以及四个对应架构的 Browser Runtime manifest/archive 资产。
