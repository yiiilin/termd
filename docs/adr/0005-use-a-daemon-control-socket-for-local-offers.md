# Use an extensible daemon control socket

termd currently has only per-session supervisor sockets, which are internal PTY transport and must not become a local CLI interface. Local daemon commands instead use a new daemon-wide control socket enabled by default at `/run/termd/termd.sock`; managed systemd installation owns the runtime directory, while manually started daemons use the same default path. Binding failure is fatal rather than silently disabling or relocating the interface, with `--control-socket` selecting another path and `--no-control-socket` providing an explicit compatibility escape for restricted environments. Its protocol is versioned and extensible through explicit commands, beginning with `file.offer`; it is not an arbitrary HTTP, terminal, or relay tunnel. The stable path lets `termd offer-file` reach the daemon from existing sessions without rebuilding them or injecting new session environment variables.

A lifetime lock serializes ownership of the socket path. A leftover entry is removed only when it is a real Unix socket in the trusted runtime directory, no listener can be reached, and its identity still matches the inspected inode; live, ambiguous, timed-out, symlink, and non-socket entries fail startup. Shutdown likewise removes only the inode created by that daemon.
